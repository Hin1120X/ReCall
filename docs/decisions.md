# Recall 开发决策

## 产品与交互

- Windows本地桌面应用，Electron + TypeScript + SQLite；不使用账号、云端数据库或跨电脑同步。
- 原型和原始交接仅本地参考，保留原文件，不作为已迁移界面，也不随源码上传。
- 0.5定稿替换早期默认新建和必填属性：双Shift默认统一搜索；Tab切全部/待办/链接，空白Down展开接续建议；+明确新增类型，搜索CtrlEnter新建；无结果Enter不创建。
- 新建只正文，链接只地址。分组及相关人可选，示例名称无专门逻辑。普通文字不通过组名展开成员，#候选确认ID后才组内过滤。
- 0.5.1根据试用补充链接命名/归组入口：新增时按需展开名称和分组，不强制填写；名称与分组同草稿保存、同事务消费。搜索卡片可直达对应链接编辑，保留未保存编辑保护，不改变打开链接的Enter行为。
- 0.5.2按用户最新要求替换链接自动取名：名称默认展开、由用户必填，未取名不创建；重名时提示修改，不自动追加序号。分组仍可选，已有链接与旧草稿保留，不批量改名。
- 工作台仅未完成/已完成两类任务视图，保留等待、暂停及未来提醒；链接并入工作台，取消独立资料窗和专用快捷键。
- 时间、紧急/重要、截止与周期由用户决定，以标签弹窗按需编辑。未编辑字段不得被默认值覆盖。
- 本地建议按到期/三日内截止、紧急、最近实际推进、重要及其他排序。未来提醒可提前开展；暂停、完成、未到跟进的等待不荐但可搜索。
- 现场、下一步、断点、备注、查看、属性和AI不算实际推进；只有明确实际进展记录更新推进时间。缺失的现场、下一步及时间不编造。
- 跟随Windows明暗，原生磨砂及实底回退；中文Noto Sans SC附OFL离线携带，英文数字使用系统Segoe，不增加字体配置器。

## 数据与可靠性

- 主进程统一写入；渲染进程仅通过受限接口，不暴露任意文件或命令操作。
- 附件保存副本，原位资料只记录路径，不移动原文件。查看和AI分析不触碰实际进展。
- 稳定ID、原时间、未知日志类型、版本化扩展字段、草稿及文件在普通编辑与升级中保留。关系字段省略则保留，显式空数组才清空。
- 升级前完整备份，事务内增量迁移，校验后提高结构版本；拒绝写入未知的更高版本，不自动降级或把备份直接覆盖当前库。
- 断点现场、历史和消费草稿同事务，事项版本冲突时保留输入。待存附件不可因简洁界面被丢弃。
- 链接草稿独立存储，双入口原子比较预期快照；冲突不盲重试。空地址且无组等价null，空地址有组继续保留。
- 重复任务完成才生成独立下一期；不批量补出遗漏周期，不复制上一期历史和附件，撤销再完成不重复生成。
- 双Shift识别与系统前台聚焦分别验收。临时提升层级后恢复，不循环抢焦点；恢复后清理按键残留，重复呼起不累积放大。
- 原数据库异常的根因没有确认，不用新回归成功替代根因说明。

## 模型与权限

- Recall调用OpenCode，由其管理认证和模型；不写密钥、不固定提供商。
- 只在主动点击分析时发送已保存文字和用户属性；不扫描或发送附件、文件夹和引用内容。
- 保存、搜索及本地建议不调用模型。常规测试只用隔离生成样例；真实模型测试需该轮明确授权。
- 翻译、术语解释、缩略语数据源尚未实现，不预建未使用执行框架。

## GitHub与发布

- 用户已授权启用Git及GitHub Releases。仓库账号、可见性、提交身份使用用户确认或真实登录信息，不编造。
- 用户确认使用公开仓库 Hin1120X/ReCall，接续已有初始提交，不强制推送覆盖历史；随后允许直接使用本人账号，提交署名沿用已核实的初始提交账号名和 GitHub 隐私邮箱，仅设置在本项目。
- 仓库只保存源码、依赖锁文件、公开开发文档及必要字体许可；原始讨论、任务数据库、附件、认证、备份和本地验收证据排除。
- 完整Windows ZIP及校验文件通过Releases交付，不把程序压缩包或node_modules提交Git。办公室下载完整包，通过离线升级保留本机数据。
- 发布前完成相关检查和本机桌面验收；CI检查与本机验收分别报告，不能把未执行的GitHub工作流称为成功。
- 2026-10-20用户确认：以后每轮开发完成默认推送GitHub、发布对应Windows Release并在本机部署核验，不再等待单独上传或部署指令。仅文档变化不增加程序版本；升级先完整备份，保存草稿、正常退出，不强杀进程。发布和本机部署分别记录真实结果，办公室仍使用Release离线升级本机数据。
